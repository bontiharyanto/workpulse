# Workpulse

**Enterprise Attendance System** — multi-tenant HRTech: kehadiran (geofence tervalidasi server), manajemen cuti, izin & sakit, lembur, pelaporan & audit.

## Tech Stack

| Layer    | Tech                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| Frontend | Next.js 15 (App Router, RSC), Tailwind CSS, Shadcn UI / Radix, TanStack Query |
| Backend  | NestJS 10 (TypeScript, DI, DTO + `class-validator`)                           |
| Database | PostgreSQL 15+                                                                |
| ORM      | Prisma 5                                                                      |
| Forms    | React Hook Form + Zod                                                         |
| Monorepo | pnpm workspaces + Turborepo                                                   |
| Testing  | Jest (backend), Vitest optional (frontend)                                    |

## Prerequisites

- Node.js **≥ 20.11** (`.nvmrc` provided)
- pnpm **≥ 9** — `corepack enable && corepack prepare pnpm@9.12.0 --activate`
- Docker **≥ 24** with Compose v2 — for Postgres (recommended) or full-stack build
- PostgreSQL **≥ 15** if you prefer running the DB natively instead of Docker

## Quick Start (recommended — Postgres via Docker)

```bash
# 1. Install dependencies
pnpm install

# 2. Copy env & fill in values (safe defaults align with docker-compose.yml)
cp .env.example .env

# 3. Start Postgres + Adminer in the background
docker compose up -d

# 4. Prepare database
pnpm db:generate
pnpm db:migrate
pnpm db:seed

# 5. Run api + web in parallel
pnpm dev
```

Frontend: <http://localhost:3000> — Backend: <http://localhost:4000/api/v1> — Swagger: <http://localhost:4000/api/docs> — Adminer: <http://localhost:8080>

## Alternative — full stack in Docker

Build and run **everything** (Postgres + api + web) inside containers. Useful for verifying production images or onboarding without Node installed:

```bash
docker compose --profile full up --build
```

The API container automatically runs `prisma migrate deploy` before booting. Seed manually once containers are healthy:

```bash
docker compose exec api node ./node_modules/prisma/build/index.js db seed
```

## Scripts

| Script                        | Purpose                                                                                       |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `pnpm dev`                    | Run api + web + shared-types watcher in parallel                                              |
| `pnpm build`                  | Build all packages via Turbo                                                                  |
| `pnpm lint`                   | Lint all packages                                                                             |
| `pnpm typecheck`              | Type-check every workspace                                                                    |
| `pnpm test`                   | Run all Jest suites                                                                           |
| `pnpm e2e`                    | Run Playwright E2E suite (needs Postgres running)                                             |
| `pnpm e2e:ui`                 | Open Playwright test UI (time-travel debug)                                                   |
| `pnpm e2e:install`            | Install Playwright's Chromium — run once                                                      |
| `pnpm db:migrate`             | Prisma migrate dev — auto-generate + apply                                                    |
| `pnpm db:migrate:create-only` | Generate migration file **without** applying (for manual edit; wajib untuk raw-SQL migration) |
| `pnpm db:migrate:deploy`      | Apply pending migrations (production)                                                         |
| `pnpm db:migrate:status`      | Show which migrations are applied vs pending                                                  |
| `pnpm db:migrate:reset`       | **DEV ONLY** — wipe DB + re-apply all migrations + seed                                       |
| `pnpm db:seed`                | Seed demo tenant + users                                                                      |
| `pnpm db:studio`              | Open Prisma Studio                                                                            |

Full migration workflow: [`docs/MIGRATIONS.md`](./docs/MIGRATIONS.md). Testing strategy: [`docs/TESTING.md`](./docs/TESTING.md).

## Auth Flow (ringkas)

- **Login** → `POST /api/v1/auth/login` mengembalikan `accessToken` (15 menit) dan `Set-Cookie: wp_refresh` (7 hari, `HttpOnly Secure SameSite=Lax`).
- **Refresh** → `POST /api/v1/auth/refresh` (pakai cookie) memicu **rotasi**: token lama ditandai `ROTATED`, token baru dikeluarkan dalam family yang sama. Penggunaan ulang token bekas → **reuse detected** → seluruh family di-revoke.
- **Logout** → `POST /api/v1/auth/logout` (revoke device ini) atau `/auth/logout-all` (revoke semua device user).
- **Forgot password** → `POST /api/v1/auth/forgot-password` selalu 202 (tidak leak keberadaan akun). Reset link 30 menit, single-use; reset sukses **me-revoke semua refresh token** user. Lihat [WORKFLOW §0.6](./docs/WORKFLOW.md) dan amandemen ADR-0002.
- Access token disimpan **in-memory** di FE (bukan `localStorage`) → tahan XSS.
- Lihat [ADR-0002](./docs/ADR/ADR-0002-auth-strategy.md) untuk rasional lengkap.

## CI / CD

- **GitHub Actions** workflow di `.github/workflows/ci.yml` menjalankan pada setiap PR dan push ke `main`:
  - `verify` — install → build shared-types → prisma generate + validate → format check → lint → typecheck → unit test → build seluruh package.
  - `docker` — build image `apps/api/Dockerfile` dan `apps/web/Dockerfile` dengan cache GHA (tidak push).
- Concurrency dikontrol per branch (push cepat berturut-turut membatalkan run lama).
- Dependabot mengupdate npm, GitHub Actions, dan base image Docker mingguan (lihat `.github/dependabot.yml`).
- `CODEOWNERS` menegakkan required review untuk area sensitif (rules, docs, infra, schema).

# 1. First-time provisioning

# 3. Verifikasi
./scripts/health-check.sh

# 4. Deploy rilis baru
IMAGE_TAG=v2026.09.01 ./scripts/deploy.sh
./scripts/rollback.sh                    # kalau perlu

# 5. Backup ops
./scripts/backup.sh                      # ad-hoc
./scripts/list-backups.sh                # inventory
AGE_IDENTITY_FILE=... BACKUP_OBJECT=... ./scripts/restore.sh   # DR drill
